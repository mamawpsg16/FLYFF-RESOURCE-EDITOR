# Task notes

Per-task facts for each editor (files, C++ functions, traps). Cross-cutting facts and rules stay in `CLAUDE.md`; deep detail is in `INVESTIGATION.md`.

- `DonationShop.inc`: prices are each item's `dwReferValue1`. It is LF (its header comment says CRLF). Categories must be leaves of the client-only `Client/Client/DonationShopTree.inc`. Never list Nexus Shield / Icecrown Purple Shield: buying them crashed the server (`ae345504`). A price above 214,769 lets a player buy 9,999 for the chips they have (`DS_OVERFLOW`, INVESTIGATION.md §1.16).
- **Donation Shop categories** (`edit/donation-ops.js`, `ui/donation-tree.js`): the editor writes the client-only tree (`Workspace.setDonationTree`, key `client/donationshoptree.inc`). A group shows the items of all its categories. The order and card text are compiled in the client (`s_szDonationCatOrder`, `DS_CategoryBlurb`) until the user builds `docs/patches/donation-tree.diff`. A name can't start with `{` / `}`. INVESTIGATION.md §1.15.
- `BattlePass.inc`: on a duplicate level or monster the first wins; values are clamped to 1–10000. LF (its header says CRLF). A season = end date + nType on the pass AND every reward row; the pass item is reused (`2f783090`). Monster prices follow level bands × rank (`c0a828d7`, `3b8e8410`).
- **Which NPCs are in the game:** placed in a map `.dyo` file (`World/<map>/<map>.dyo`, maps from `World.inc`) AND shown by `CWorld::IsUsableDYO2` (`SetOutput` / `SetLang` in `character.inc`). The WorldServer's language is compiled in: `WorldServer.rc:137` `IDS_LANG "1"` = LANG_USA. Ported in `loaders/world.js`; skip commented lines (the real loader does).
- **Adding an NPC** (`edit/npc-ops.js`, "+ New NPC" in NPC Shops): the key defaults to the region's usual start + the name (`newNpcSim.keyPrefix`, from the keys of the NPCs standing there) until typed by hand; a block appended to character.inc, IDS lines appended to character.txt.txt, a 200-byte record inserted at the map `.dyo`'s final `FFFFFFFF`, x and z stored ÷ 4. All three in Server + Client. A new building tag adds `SRT_` lines to defineNeuz.h + etc.inc + etc.txt.txt (`b4b9a465`); only rows 18/19 are free (`MAX_STRUCTURE` 20 is compiled). Tested in game by the user (2026-10-08): the new NPC stands, Trade, Exchange and Rules text menus work. Details: INVESTIGATION.md §1.9.
- **Where an NPC stands** (`loaders/area.js`): `.dyo` x/z × 4 (`OLD_MPU`). The map-window name comes from the `WdMadrigal.wld.cnt` polygons and `propMapComboBoxData.inc`. The on-screen area name comes from the map's `.rgn` titles. Town blocks in `.wld.cnt` have `C_useRealData 0`, so the map window never picks a town. A GM jumps there with `/te <world id> <x> <z>`.
- **Shop prices** (`loaders/vendor-sim.js`, INVESTIGATION.md §1.12): one `dwCost` per item; the last `AddShopItem` price loaded (Masquerade.prj: character.inc, -etc, -school) is the price in every shop, rule shops included. Players pay `(int)(rate × cost)` in float32, at least 1 (cost "=" or 0 → 1; from 2,147,483,584 the float overflows → 1); they get back cost / 4. An edit on an "auto" row (from `AddVendorItem`) first gives each auto item of the tab its own `AddShopItem` line, same order, with no extra window (`ui/shop-rules.js`); a typed price is also written on the item's other priced lines (`shopOps.otherPriceParts`).
- **Try it before Create** (`ui/menu-form.js`, every exchange card in + Menu › Exchange, + NPC, ⇄ tab + New exchange): runs `menuOps.tryTable` on what Create would write (empty label / taken name get stand-ins) and opens the ⇄ tab's Try window (`exchangeView.openTry`). Nothing in the workspace changes.
- **Editing chances:** the UI types percent and keeps the total at 1,000,000 (`exchangeOps.rebalance`); NPC Shops shows each exchange menu of an NPC as a tab with the Exchanges cards.
- **Moving an NPC / changing its model** (`npcEditOps.placePlan`, NPC Shops "📍 Change position / model" (next to the name)): rewrites the record's facing (byte 4), x/y/z (20/24/28, x and z ÷ 4) and model (`m_dwIndex`, 48) in place, same file size, the `b6abf414` way; one spot at a time, the model optionally on every spot; same map only. **Paste from the game** reads the `/position` chat line ("Position : x = %f, y = %f, z = %f", `FuncTextCmd.cpp:3955`); **Face toward** a second line sets the facing with `GetDegree` (`Obj.h:288`: 0 = toward -z, 90 = +x). Shared form fields: `ui/npc-place.js`. INVESTIGATION.md §1.14.
- **Editing an existing NPC** (`edit/npcedit-ops.js`, NPC Shops ✎ / + Tab / + Menu): name and tab texts are `character.txt.txt` lines (`f58e56ba`, `ba92f67f`); a shared key (`000049` "n/a" ×6) gets a new key for this NPC/tab unless "everywhere" is asked; + Tab = key line + `AddVendorSlot( n, KEY );` after SetName (`d11123ac`). The shop window shows only named tabs, at their slot's position; slot 0 unnamed with a later slot named crashes the client on a tab click (`C_TAB_FIRST_UNNAMED`). character.inc NPCs only. INVESTIGATION.md §1.11.
- **Item list categories** (`loaders/item-category.js`): the editor's own groups from dwItemKind1/2/3; pets follow `IsVisPet` (`IK3_PET` + `dwReferStat1 == PET_VIS` = buff pet), `IK3_EGG` = raised. Rarity chips only for Weapons / Armor.

- **Monster drops** (`loaders/drops.js`, `edit/drops-ops.js`, task "Monster Drops", INVESTIGATION.md §1.18): `propMoverEx.inc` is server-only (drops kept `#ifdef __WORLDSERVER`, no loose Client copy), UTF-8 with U+FFFD in old comments, CRLF. Chances are out of 3,000,000,000, read with atoi (capped at 2,147,483,647), and the roll is `xRand() % 3e9`, so low values come ~1.4× more often: the editor shows and types the **real** chance (a "10%" line = 13.97%, the cap = 80.15%). Script-made blocks (`// [BossDrop] begin`, `[SetDrop]`, `[TowerCard]`, `[RedChip]`, `[MoonSun]`, from `gen_*.ps1` in the guides repo) are editable with a ⚠ `M_GEN_EDITED` (the user's choice, 2026-10-08). - **Mounts** (task "Mounts", `loaders/mounts.js`, `loaders/mount-sim.js`, `edit/mounts-ops.js`, `validate/mounts.js`, `ui/mounts.js`, INVESTIGATION.md §1.29): `Mount.inc` (UTF-16LE, CRLF, identical Client copy; the WorldServer and the game at start, `LoadMountAnimationList` Project.cpp:1102) = what `/mountset` tunes. **The page opens simple** (the user, 2026-10-18: "only change the animation walk/run speed and the fly speed ... layman terms"): Legs when running (fAnimSpeed), Legs when walking (fWalkAnimSpeed), Flying speed typed as the speed-meter number (`mountSim.pushForMeter` finds the push, and raises the top speed to 2 only when it would cut the flight short); everything else is under a closed "More settings": speed (replaces the rider's speed: buffs do nothing), leg speeds, the stand / run / walk / back loops (picked from the model's own `.ani` files: `Client/Model.list`), "can fly" (nType 1 only), flying push / top speed / leg speed / fly loops, name height, seat. A missing key = the loader default (fGroundSpeed 0 = can't move); the last block of an id wins; a block without `}` hangs the startup (`MT_UNCLOSED`). **Paste from /mountset** reads its reply; **Copy from another mount** (speeds by default; loops / seat optional); **+ Add Mount.inc block** for a mount item without one (the template's lines + the model's own loops). Floats are written back short (0.4, not 0.4000000059604645). The dragons' flying top speed 0.9 is never reached (push vs air friction: shown as a warning line).
- **Economy** (task "Economy", `loaders/spawns.js`, `loaders/economy-sim.js`, `ui/economy.js`, INVESTIGATION.md §1.34, plan `docs/plans/E-economy.md`): read-only (`MODULES` id `economy`, `uses` drops / npc / donation / upgrade, `maps: true`: needs `World/<map>/<map>.rgn`). A spot = a map + a monster (every spawn box of it on that map). Per hour = min( kill speed, the spot's respawn cap ) x 60 x per kill; Penya and loot from drops-sim kills (seeded, 300 / 1,000 / 3,000), the 3 currencies from the exact chance. The respawn is fast (most boxes refill every ~12-15 s), so for one player the kill speed decides, except at 1-2 monster spots (bosses, Dekane Mine leaders). Prices in hours: Penya / Perin at the best Penya spot, Red Chips at the best Red Chip spot; Donate Chips, PVP / Event Tokens are not from monsters. Upgrades: +0 -> +10 weapon / armor (Sunstones + SMELPROT) and jewelry (Moonstones + SMELPROT4), upgrade-sim `expect`; no UpgradeFees.lua = the compiled fees. Computed numbers live in `mem`, not `st` (the app JSON-stringifies `st` to spot a new view).
- `Exchange_Script.txt`: a bare `CScanner`, so an unknown name becomes -1 silently (`GetDefineNum`). `__NEW_EXCHANGE_V19` is ON (`LodeConfig.h`): CONDITION is checked and taken, REMOVE is ignored, at most 30 SETs per menu. PAY chances are out of 1,000,000. The client sends only the recipe's position, so the Client copy (LF) must match. `SET_SMELT` / `SET_ENCHANT_MOVE` put the loader out of step (see ROADMAP).
  - In game (`exchange-sim.js`): the roll happens before the bag check; the bag check wants at least one EMPTY slot even when the reward would stack, and counts a reward smaller than a full stack as 0 slots, so a recipe giving several rewards can lose some (the server only logs it). Penya means gold only (not Perin). Any item in a trade / private shop or a locked bag slot makes every ingredient count 0. Ingredient quantity -1 takes every one the player has.
