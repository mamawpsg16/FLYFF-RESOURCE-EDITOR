## What the C++ does (port these, cite file:line)
- **Loader** `CProject::LoadPiercingAvail` (`_Common/Project.cpp:4567-4611`, called `:861` on both): `SetItem <id> <IDS name> { Elem { II_X PARTS_Y … } Avail { DST_X adj pieces … } }`. Limits: 8 pieces (`MAX_SETITEM_ELEM`, a 9th is dropped, TRACE only), 32 bonus rows (`MAX_ITEMAVAIL`), name 64 chars. Rows sorted by pieces (stable bubble, `SortItemAvail :4736`).
- **Finder** `CSetItemFinder::AddSetItem :4806`: set id → set keeps the FIRST (map insert); item id → set keeps the FIRST. **Found:** set id 1 is written twice (lines 478 and 499 of the UTF-8 view): the second set's bonuses still work by item id, but its tooltip (looked up by id, `GetEquipedSetItem`) shows the first set's pieces.
- **Bonus** `CMover::SetDestParamSetItem` (`Mover.cpp:9853`): at login / full recalc (`MoverEquip.cpp:2193`) counts worn set items by item id in ANY slot; when one item is put on (`:2458`) counts only pieces in their own listed slot (`GetEquipedSetItemNumber :9913`) and adds the rows for exactly that count; take-off `ResetDestParamSetItem :9898`. Expired items don't count. `GetItemAvail :4760` sums same-DST rows.
- **+N bonus** `expTable.inc` `Setitem` (`Project.cpp:3829`): 10 rows (+1..+10) × HitRate, Block (melee + range), Max HP %, AddMagic, Added (STR/DEX/INT/STA each). `GetSetItem` (`Mover.cpp:9562`): the lowest +N of the 4 armor parts (suit, hand, foot, cap), all worn and not expired; `GetSetItemAvail :4535` = row n-1, nothing above +10 or at 0. `SetSetItemAvail :9654`.
- **Tooltip** `CWndMgr::PutSetItemOpt` (`_Interface/WndManager.cpp:5553`, 70f8c863): "Name (worn/total)", pieces green / amber (in bag) / grey, every tier "Set Effect (Npc):" bright when reached, rate stats as %.
- **Names**: `propItemEtc.txt.txt` (UTF-16, server only today; the game reads the old copy in data.res).
